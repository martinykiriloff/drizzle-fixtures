# CLI — npx drizzle-fixtures generate

Reads your Drizzle schema and generates typed factory files.

## Usage

```bash
# Generate factories for all tables
npx drizzle-fixtures generate --schema ./src/db/schema.ts --out ./tests/factories

# Single table only
npx drizzle-fixtures generate --schema ./src/db/schema.ts --out ./tests/factories --table users

# Dry run — print to stdout, write no files
npx drizzle-fixtures generate --schema ./src/db/schema.ts --dry-run
```

## Options

| Flag | Short | Description |
|------|-------|-------------|
| `--schema` | `-s` | Path to your Drizzle schema file (required) |
| `--out` | `-o` | Output directory for generated factories |
| `--table` | `-t` | Generate only this table (by table name) |
| `--dry-run` | | Print output to stdout, write no files |

## Generated output

For a `users` table and a `blog_posts` table:

```
tests/factories/
├── user.factory.ts
├── blog-post.factory.ts
└── index.ts
```

`user.factory.ts`:
```ts
// Auto-generated by drizzle-fixtures. Do not edit manually.

import { defineFactory } from 'drizzle-fixtures'
import { users } from '../../src/db/schema.js'

export const userFactory = defineFactory(users)
```

`index.ts`:
```ts
// Auto-generated by drizzle-fixtures. Do not edit manually.

export { userFactory } from './user.factory.js'
export { blogPostFactory } from './blog-post.factory.js'
```

## Name conversion

| Table name | Factory variable | File name |
|------------|-----------------|-----------|
| `users` | `userFactory` | `user.factory.ts` |
| `blog_posts` | `blogPostFactory` | `blog-post.factory.ts` |
| `userProfiles` | `userProfileFactory` | `user-profile.factory.ts` |

## Notes

- The schema must be loadable with `import()` — compile it with `tsc` first, or use `tsx` / `ts-node`
- Re-running overwrites existing files (idempotent)
- Generated factories use `defineFactory` with no overrides — customise them after generation
